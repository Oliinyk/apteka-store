# ВІТА — локальна аптека з адмінкою

Інтернет-вітрина аптеки: безрецептурні препарати, дієтичні добавки, догляд і
медтехніка. Каталог з фільтрами, картка товару, кошик, оформлення замовлення
та повноцінна адмінка. Без жодної npm-залежності — працює на вбудованих
модулях Node.js (`node:http` + `node:sqlite`).

Це навчальний локальний проєкт, а не справжня аптека: жодних реальних
замовлень він не приймає й нікуди не передає. У каталозі лише безрецептурні
позиції та дієтичні добавки, тексти описів — загального характеру, без
рекомендацій щодо лікування.

## Запуск

```bash
cd /Users/home/work/apteka-store
npm start
```

Потрібен Node.js 22.5+ (у вас v24 — усе ок). База, товари та картинки
створюються автоматично при першому запуску.

- Вітрина: http://localhost:3001
- Адмінка: http://localhost:3001/admin

Інший порт: `PORT=8080 npm start`
Автоперезапуск при зміні коду: `npm run dev`

## Вхід в адмінку

| Адреса | http://localhost:3001/admin |
|---|---|
| Логін | `admin` |
| Пароль | `admin123` |

Посилання на адмінку також є внизу кожної сторінки сайту (праворуч у підвалі).

Пароль і логін міняються прямо в адмінці: розділ **Акаунт** у бічному меню.
Треба ввести поточний пароль, новий (від 6 символів) і його повтор. Після зміни
пароля всі інші сесії розлогінюються, а підказка з дефолтними даними зникає зі
сторінки входу.

Якщо пароль забуто — скинути можна командою:

```bash
node --disable-warning=ExperimentalWarning -e "import('./src/db.js').then(({db,hashPassword})=>{const {salt,hash}=hashPassword('admin123');db.prepare('UPDATE users SET username=?, hash=?, salt=? WHERE id=1').run('admin',hash,salt);console.log('скинуто на admin/admin123')})"
```

## Що є в адмінці

- **Огляд** — лічильники товарів, замовлень, сума продажів, залишки, що закінчуються.
- **Товари** — створення, редагування, видалення. Назва, URL, категорія, ціна і стара
  ціна (знижка рахується автоматично), залишок, артикул, короткий і повний опис,
  характеристики, плашки «Новинка»/«Хіт», приховування товару.
- **Галерея фото** — можна вибрати одразу кілька файлів (або кинути їх у поле вибору),
  вони завантажуються відразу й одразу видно прев'ю. Порядок змінюється
  перетягуванням картки або стрілками `←` `→`; кнопка `★` робить фото головним,
  `✕` — видаляє. Перше фото у списку — головне, воно показується в каталозі;
  решта стає галереєю на картці товару. Є й кнопка «Додати за посиланням» для
  зовнішнього URL. Без JavaScript форма теж працює: файли, вибрані в полі,
  додаються в кінець списку при збереженні.
- **Категорії** — CRUD, кількість товарів у кожній.
- **Замовлення** — список із фільтром за статусом, картка замовлення зі складом і
  контактами, зміна статусу (нове → підтверджено → відправлено → виконано / скасовано).
- **Тексти сайту** — редагування **всіх** текстів вітрини: верхня смуга, банер
  (заголовок, опис, кнопка, картинка), 4 блоки переваг, заголовки каталогу, блок
  «про аптеку» з цифрами, підписи кошика й оформлення, способи доставки та оплати,
  контакти, підвал, SEO-теги, а також **застереження** (показується в підвалі
  кожної сторінки та на картці кожного товару; якщо поле очистити — зникає).
- **Акаунт** — зміна логіна й пароля адміністратора.
- **Сторінки** — довільні текстові сторінки (Про нас, Доставка, FAQ, Контакти);
  галочка «показувати в меню» виводить сторінку в шапку й підвал.

## Що є на вітрині

Головна (банер, переваги, товари, категорії, про аптеку) · каталог із пошуком,
фільтром за категорією та сортуванням · картка товару з характеристиками
(діюча речовина, форма випуску, умови відпуску), галереєю та схожими позиціями ·
кошик у localStorage · оформлення замовлення з розрахунком безкоштовної доставки ·
текстові сторінки (Про нас, Доставка, Обмін і повернення, FAQ, Контакти) · 404.
Застереження про самолікування виводиться в підвалі й на кожній картці товару.
Адаптив під мобільні.

Після оформлення замовлення залишок товару автоматично зменшується.

## Деплой на безкоштовний хостинг

Проєкт — це звичайний Node-сервер із файловою базою SQLite, тому йому потрібен
хостинг, що тримає постійний процес і має диск. **Vercel не підходить**: там
serverless-функції з файловою системою лише для читання, база й завантажені фото
не збережуться. Підходять Render, Koyeb, Fly.io, будь-який VPS.

### Render (безкоштовний тариф)

1. Запуште репозиторій на GitHub.
2. На render.com → **New** → **Web Service** → підключіть цей репозиторій.
3. Render сам прочитає `render.yaml`. Якщо заповнюєте руками:
   - Runtime: **Node**
   - Build Command: `npm install`
   - Start Command: `npm start`
4. У розділі **Environment** додайте змінні:
   - `ADMIN_USER` — ваш логін адміністратора
   - `ADMIN_PASSWORD` — ваш пароль (обовʼязково, посилання ж публічне)
5. Deploy. Через кілька хвилин буде посилання виду `https://vita-store.onrender.com`.

Змінні оточення, які розуміє застосунок:

| Змінна | Призначення | За замовчуванням |
|---|---|---|
| `PORT` | порт сервера | `3001` |
| `DATA_DIR` | тека для `store.db` | `./data` |
| `ADMIN_USER` | логін адміна при першому запуску | `admin` |
| `ADMIN_PASSWORD` | пароль адміна при першому запуску | `admin123` |

### Що треба знати про безкоштовний тариф

- Сервіс **засинає** після ~15 хвилин без запитів; перший запит після сну
  прокидає його 30–50 секунд.
- Диск **непостійний**: після кожного деплою чи перезапуску база й завантажені
  фото скидаються, каталог наповнюється стартовими даними заново. Для демо це
  нормально; щоб дані зберігалися, потрібен платний диск Render
  (тоді вкажіть `DATA_DIR=/var/data` і змонтуйте туди диск) або зовнішня БД.
- `ADMIN_USER`/`ADMIN_PASSWORD` діють лише на **порожній** базі, тобто після
  кожного скидання — тому пароль із цих змінних і буде актуальним.

## Скидання до заводських даних

```bash
npm run reset
```

Видаляє `data/store.db` і наповнює базу заново (картинки в `public/uploads` лишаються).

## Примітки

- Сесії зберігаються в пам'яті процесу — після перезапуску сервера треба увійти знову.
- Магазин-близнюк у кавовій тематиці лежить поруч: `/Users/home/work/zerno-store` (порт 3000).
  Код у них спільний, різниця лише в даних `src/seed.js`, кольорах і картинках.
- Проєкт розрахований на локальний запуск. Для публічного хостингу потрібні
  HTTPS, зміна пароля, обмеження на кількість спроб входу та CSRF-токени у формах.
